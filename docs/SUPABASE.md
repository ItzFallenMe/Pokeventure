# Supabase setup (social)

> Part of the [documentation index](README.md). Setting up the app for the first
time? Follow [SETUP.md](SETUP.md) and come back to this page when you reach the
Social step.

The Social tab keeps trainer cards and friendships in Supabase Postgres and
talks to it directly from the app. Battles stay on the game server; Supabase is
only identity + social data, so the free project tier is enough for a long time.

The app uses **anonymous sign-in**, so a player can use the Social tab without
an email or password. The session is persisted on the device by
`supabase_flutter`; the same Supabase user id owns the trainer card. Email or
OAuth can be added later without losing the profile.

## 1. Create the project

1. [supabase.com](https://supabase.com) → **New project** (free plan).
2. Note the **Project URL** and the **anon public** key from
   *Project Settings → API*. Newer dashboards call this key the **publishable
   key**; it is the same value and the same env var here.

The anon/publishable key is safe to ship in a mobile app; row-level security is
what protects the data. Never put the `service_role` key in the app.

## 2. Enable anonymous sign-ins

*Authentication → Providers → Anonymous sign-ins → Enable.*

If this is off, the Social tab reports that it could not sign in and everything
else in the app keeps working.

## 3. Create the tables

*SQL Editor → New query*, paste the contents of
[`supabase/migrations/0001_social.sql`](../supabase/migrations/0001_social.sql)
and run it. It is idempotent, so re-running is safe.

That creates:

| Table | Purpose |
|---|---|
| `players` | Trainer name, unique 6-character friend code, last seen |
| `friendships` | Requests and accepted friendships, one row per pair |

Row-level security is on for both. Players can read trainer cards, edit only
their own, send requests as themselves, answer only requests addressed to them,
and either side can remove a friendship.

## 4. Point the app at it

Pass both values at build time:

```bash
cd app
flutter build apk --release \
  --dart-define=SUPABASE_URL=https://YOUR-PROJECT.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=YOUR_ANON_KEY \
  --dart-define=API_BASE_URL=https://pokeventure-server.onrender.com
```

For `flutter run` the same flags work. For the GitHub Actions APK, add repository
variables (*Settings → Secrets and variables → Actions → Variables*):
`SUPABASE_URL`, `SUPABASE_ANON_KEY`, plus `API_BASE_URL`.

The workflow forwards them to `flutter build apk`.

Without these values the Social tab shows a setup card and the rest of the app
is unchanged — nothing crashes and no fake friends are shown.

## 5. Friend codes and QR

Every trainer gets a unique six-character code (no `0/O/1/I`) generated by the
database. The Social tab shows it as text and as a QR code. Scanning a code in
the app — or typing it — sends a friend request. Accepting is a single tap.

The QR contains only the friend code, which is a lookup key, not a secret: it
can only be used to *request* a friendship, never to act as you.

## Costs and limits

The free tier includes 500 MB of Postgres, 50,000 monthly active users and
unlimited API requests. Trainer cards and friendship rows are tiny. The project
pauses after a week of inactivity; open the dashboard to wake it.
